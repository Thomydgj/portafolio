CASE STUDY 01 · ELEGANZA

Keeping physical and online inventory in sync.

The problem

Eleganza operates physical stores across Colombia and an online Shopify store. Inventory could become inconsistent between Shopify and Mahalo, creating situations where the website showed stock that did not physically exist, or hid stock that was actually available.

The solution

I built a bidirectional synchronization service in Python on AWS. Shopify sales trigger webhooks; Mahalo inventory movements are checked periodically through Kardex data because the platform did not provide an equivalent immediate event.

Architecture

The system extracts SKU and quantities, applies the corresponding inventory movement and records the online-sale context in Mahalo.

CASE STUDY 02 · GRUPO ANDINO INMOBILIARIO

From one property entry to automatic website publishing.

The problem

Properties were created in SIMI and then manually recreated in WordPress, duplicating the same work and increasing the possibility of inconsistent information.

The solution

Every 15 minutes, a Python process checks SIMI for new property codes, retrieves the property data and images, transforms the information into the structure required by WPResidence and sends it through the WordPress API.

Architecture

Processed property codes are stored so the same property is not created twice.
